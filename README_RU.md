## Использование

Всё предельно просто: создается `MorphAnalyzer` со встроенным словарем, затем вызываются методы анализа и словоизменения.

Пример:
```rust
use rs_morphy4::MorphAnalyzer;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let morph = MorphAnalyzer::default();
    for parse in morph.parse("кошки")? {
        println!("{}: {}", parse.normal_form, parse.tag);
        if let Some(form) = morph.inflect(&parse, ["plur", "gent"])? {
            println!("{}", form.word);
        }
    }
    Ok(())
}
```

`MorphAnalyzer::default()` использует готовый русский словарь, встроенный в библиотеку (ну т.е. буквально из этого репозитория). Настройка путей и отдельные файлы при запуске не нужны.

`MorphAnalyzer::new(dictionary)` принимает пользовательский словарь через структуру `DictionaryData`. Его файлы тоже можно встроить в приложение с помощью `include_bytes!`:

```rust
use rs_morphy4::{DictionaryData, MorphAnalyzer};

let dictionary = DictionaryData {
    metadata: include_bytes!("my_dictionary/meta.json"),
    grammemes: include_bytes!("my_dictionary/grammemes.json"),
    tags: include_bytes!("my_dictionary/gramtab-opencorpora-int.json"),
    suffixes: include_bytes!("my_dictionary/suffixes.json"),
    paradigms: include_bytes!("my_dictionary/paradigms.array"),
    words: include_bytes!("my_dictionary/words.dawg"),
    prediction_suffixes: None,
};
let morph = MorphAnalyzer::new(dictionary)?;
```

Поддерживаются русские словари в формате pymorphy 2.4 со структурой файлов как в `data/dicts_ru`. `DictionaryData` принимает байты из памяти или `include_bytes!`; пути в макросе отсчитываются от Rust-файла. `MorphAnalyzer::load("путь/к/словарю")` загружает словарь из папки при запуске.

`prediction_suffixes` принимает таблицы суффиксного прогноза в порядке префиксов парадигм. При `None` действуют запасные правила. Встроенный словарь содержит полный комплект таблиц; `load(path)` загружает их при наличии.

`tag`, `normal_forms` и `word_is_known` возвращают теги, леммы и признак наличия слова в словаре. `lexeme`, `normalized`, `inflect` и `make_agree_with_number` работают с выбранным `Parse` из того же словаря. При отсутствии подходящей формы склонение возвращает `None`, при некорректных ссылках на парадигму возникает `InflectionError`. `DictionaryAnalyzer` предоставляет поиск только по словарю.

## Поведение

Всё просто. Пробелы по краям удаляются, регистр понижается. Пустой ввод не дает разборов. `default`, `new` и `load` ранжируют результаты по встроенным частотам слова и тега. При равных или отсутствующих частотах учитываются вес правила, часть речи, именительный падеж и число граммем. `Parse.score` остается весом правила, а не вероятностью. `parse_unranked` сохраняет порядок правил и обходит кеш.

`morph.with_probabilities(None)` отключает статистическое ранжирование, а `morph.with_probabilities(Some(Arc::new(model)))` подключает пользовательский `WordTagProbabilities`.

Клоны анализатора разделяют словарь и потокобезопасный FIFO-кеш на 1024 токена. `MorphAnalyzer::from_shared(morph.shared_dictionary(), capacity)` создает анализатор с эвристическим ранжированием и отдельным кешем заданного размера; емкость 0 отключает кеш.

Известные ограничения/допущения:

- Словарный поиск проверяет независимые замены `е` -> `ё` по существующим ветвям DAWG. Явная `ё` сохраняется; прогноз используется, только если словарные разборы не найдены.
- Неизвестные слова разбираются по словарным основам и суффиксным моделям. Прогноз может содержать несколько вариантов. У разборов без парадигмы лексема содержит одну форму.
- При согласовании с отрицательным числом форма слова может отличаться от формы для такого же положительного числа: например, `1 кошка`, но `-1 кошек`. Это особенность текущего алгоритма `make_agree_with_number`.
- Частоты слова и тега не учитывают контекст предложения. Первый разбор может оказаться неподходящим для конкретной фразы.
- При загрузке проверяется структура таблиц; переходы и записи DAWG проверяются при обращении к ним.

## Контекстный анализ

`parse_context(tokens)` разбирает последовательность токенов с учетом соседних слов. Знаки препинания передаются отдельными токенами.

```rust
let result = morph.parse_context(["Мы", "будем", "вести", "переговоры", "."])?;
let reading = result[2].decision.selected.as_ref().unwrap();
assert_eq!((reading.lemma.as_str(), reading.pos.as_str()), ("вести", "INFN"));
```

Результат содержит исходные `candidates`, выбранную лемму и часть речи в `decision.selected`, альтернативы в `decision.retained` и сработавшие правила в `decision.support`. При неоднозначности `selected` равен `None`: например, для "Я плачу" остаются платить и плакать. Веса правил не являются вероятностями.

Контекстные правила учитывают согласование и управление. Это локальные эвристики: они могут ошибаться и не всегда разрешают смысловую неоднозначность.

Ниже измерено эвристическое ранжирование с суффиксным прогнозом. Частоты слова и тега и контекстный анализ отключены.

Моя конфигурация при которой делал бенчмарки:

```text
Ryzen 7 7800X3D
Linux x86_64
Rust 1.98.0
оптимизированная сборка
```

Словарь загружается через `load(path)`. В таблице приведены медианы пяти запусков каждого режима; загрузка через `default()` и `new(dictionary)` не измерялась.

| Режим кеша | Вызовов разбора/с | Загрузка словаря, мс | RSS процесса после обработки, МиБ |
| --- | ---: | ---: | ---: |
| Без кеша | 326,936 | 9.76 | 22.9 |
| 1024 записи (по умолчанию) | 300,741 | 9.78 | 22.9 |
| 2504 записи (весь корпус) | 1,715,518 | 9.48 | 23.7 |

Перед измерением кеш прогревался одним проходом корпуса. При емкости 1024 записи корпус не помещается в кеш: циклический обход вытесняет записи до повторного обращения, поэтому попаданий нет. При емкости 2504 записи все непустые входы находятся в кеше.

RSS отражает память всего процесса, включая словарь и кеш. Время загрузки измерено без очистки файлового кеша ОС. [Методика и исходные измерения](benchmarks/README.md) содержат подробные условия и все результаты запусков.

## DAWG и использованная литература

Если СОВСЕМ КОРОТКО, то DAWG (Directed Acyclic Word Graph) представляет собой набор строк как ориентированный ациклический граф. В словарном варианте это детерминированный конечный автомат: состояния с одинаковыми допустимыми продолжениями объединяются, что позволяет компактно хранить словарь. Построение таких автоматов описано в работе:

- J. Daciuk, S. Mihov, B. W. Watson, R. E. Watson. [Incremental Construction of Minimal Acyclic Finite-State Automata](https://aclanthology.org/J00-1002/). Computational Linguistics, 26(1), 2000, с. 3-16. [PDF](https://aclanthology.org/J00-1002.pdf).

Практическая реализация этой структуры в [dawgdic](https://github.com/stil/dawgdic) использует представление double-array. На ней то основана библиотека [DAWG](https://github.com/pytries/DAWG). В `rs-morphy4` модуль [dictionary/dawg](src/dictionary/dawg) читает готовый бинарный индекс и извлекает записи с номерами парадигм и форм. Построение и минимизация автомата в текущей версии библиотеки я не делал. Может, в будущем, если будет необходимость, я и сделаю. Впрочем, для русского языка словарь в 2,5 млн слов и 1,5 млн форм занимает всего с десяток МБ, поэтому особой нужды в этом нет, мне кажется.
