# rs-morphy4

[![Версия на crates.io](https://img.shields.io/crates/v/rs-morphy4.svg)](https://crates.io/crates/rs-morphy4)

[English version](README.md)

[Очередной](https://www.youtube.com/watch?v=jEI3N9kIyP4) морфологический анализ и словоизменение русского языка (однако, реализованно на Rust): леммы, грамматические теги, прогноз неизвестных слов, составные слова, лексемы и согласование с целыми числами. Библиотека обрабатывает отдельные токены; токенизация и снятие неоднозначности по контексту в ее задачи не входят.

## Использование

Всё предельно просто: создается `MorphAnalyzer` со встроенным словарем, затем вызываются методы анализа и словоизменения.

Пример:
```rust
use rs_morphy4::MorphAnalyzer;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let morph = MorphAnalyzer::default();
    for parse in morph.parse("кошки")? {
        println!("{}: {}", parse.normal_form, parse.tag);
        if let Some(form) = morph.inflect(&parse, ["plur", "gent"])? {
            println!("{}", form.word);
        }
    }
    Ok(())
}
```

`MorphAnalyzer::default()` использует готовый русский словарь, встроенный в библиотеку (ну т.е. буквально из этого репозитория). Настройка путей и отдельные файлы при запуске не нужны.

`MorphAnalyzer::new(dictionary)` принимает пользовательский словарь через структуру `DictionaryData`. Его файлы тоже можно встроить в приложение с помощью `include_bytes!`:

```rust
use rs_morphy4::{DictionaryData, MorphAnalyzer};

let dictionary = DictionaryData {
    metadata: include_bytes!("my_dictionary/meta.json"),
    grammemes: include_bytes!("my_dictionary/grammemes.json"),
    tags: include_bytes!("my_dictionary/gramtab-opencorpora-int.json"),
    suffixes: include_bytes!("my_dictionary/suffixes.json"),
    paradigms: include_bytes!("my_dictionary/paradigms.array"),
    words: include_bytes!("my_dictionary/words.dawg"),
};
let morph = MorphAnalyzer::new(dictionary)?;
```

Пути в `include_bytes!` отсчитываются от Rust-файла с этим кодом и нужны только при сборке. Пользовательский словарь должен иметь такую же структуру файлов, как data/dicts_ru. Поддерживаются словари русского языка в формате pymorphy 2.4 - иначе, закономерно, случится ошибка чтения. Вместо встроенных файлов `DictionaryData` также принимает данные из памяти. Для загрузки словаря из папки при запуске остается `MorphAnalyzer::load("путь/к/словарю")`.

Методы `tag`, `normal_forms` и `word_is_known` предоставляют отдельные результаты анализа. Методы `lexeme`, `normalized`, `inflect` и `make_agree_with_number` принимают `Parse` из того же словаря. Если подходящей формы нет, склонение возвращает `None`; некорректные ссылки на словарь возвращают типизированные ошибки. `DictionaryAnalyzer` предоставляет поиск только по словарю.

## Поведение

Всё просто. Пробелы по краям удаляются, регистр понижается. Пустой ввод не дает разборов. `default`, `new` и `load` ранжируют результаты по встроенным частотам слова и тега. При равных или отсутствующих частотах сохраняется порядок эвристик: словарность, часть речи, именительный падеж, число граммем. `Parse.score` остается весом правила, а не вероятностью. `parse_unranked` сохраняет порядок правил и обходит кеш.

`morph.with_probabilities(None)` отключает статистическое ранжирование. `morph.with_probabilities(Some(Arc::new(model)))` подключает пользовательский `WordTagProbabilities`, загруженный из байтов DAWG (целочисленного) и таблицы тегов. Замена модели создает пустой независимый кеш; существующие клоны сохраняют свои модель и кеш. Модель сопоставляет точные грамматические признаки, а не номера парадигм, в том числе для пользовательских словарей.

Клоны анализатора разделяют неизменяемый словарь и потокобезопасный FIFO-кеш. По умолчанию он вмещает 1024 нормализованных токена. `MorphAnalyzer::from_shared(morph.shared_dictionary(), capacity)` создает анализатор с эвристическим ранжированием и отдельным кешем; емкость 0 отключает хранение. Результаты возвращаются независимыми копиями. При одновременных промахах один токен может вычисляться несколько раз.

Известные ограничения/допущения:

- Словарный поиск проверяет независимые замены `е` -> `ё` по существующим ветвям DAWG. Явная `ё` сохраняется; прогноз используется, только если словарные разборы не найдены.
- Неизвестные и составные слова обрабатываются правилами. У синтетических разборов без парадигмы лексема содержит одну форму.
- При согласовании с отрицательным числом форма слова может отличаться от формы для такого же положительного числа: например, `1 кошка`, но `-1 кошек`. Это особенность текущего алгоритма `make_agree_with_number`.
- Частоты слова и тега не учитывают контекст предложения. Первый разбор может оказаться неподходящим для конкретной фразы.
- При загрузке проверяется структура таблиц; переходы и записи DAWG проверяются при обращении к ним.

## Примеры и проверка

Из корня репозитория можно запустить примеры и тесты:

```sh
cargo run --example analyze -- стали
cargo run --example inflect
cargo run --example custom_dictionary
cargo test --locked
cargo doc --no-deps
```

Проверка корпуса в эвристическом режиме сохраняет совпадение с закрепленным эталоном. Статистическое ранжирование отдельно проверяется по целочисленным частотам и ожидаемым первым леммам. Если интересно, то вот [описание тестов](tests/README.md) содержит границы покрытия и намеренные отличия.

Приведенные ниже измерения относятся к эвристическому ранжированию до добавления частотной модели; скорость статистического ранжирования ими не измеряется.

Моя конфигурация при которой делал бенчмарки:

```text
Ryzen 7 7800X3D
Linux x86_64
Rust 1.98.0
оптимизированная сборка
```

Результаты для загрузки словаря через `load(path)` до встраивания. Для `default()` и `new(dictionary)` отдельные измерения пока не проводились - да оно и не нужно, думаю. В таблице приведены медианы пяти запусков каждого режима.

| Режим кеша | Вызовов разбора/с | Загрузка словаря, мс | RSS процесса после обработки, МиБ |
| --- | ---: | ---: | ---: |
| Без кеша | 401 583 | 8,36 | 15,3 |
| 1024 записи (по умолчанию) | 361 941 | 8,28 | 17,3 |
| 2504 записи (весь корпус) | 1 754 965 | 7,93 | 19,7 |

Перед измерением кеш прогревался одним проходом корпуса. При емкости 1024 записи корпус не помещается в кеш: циклический обход вытесняет записи до повторного обращения, поэтому попаданий нет. При емкости 2504 записи все непустые входы находятся в кеше.

RSS отражает память всего процесса, включая словарь и кеш. Время загрузки измерено без очистки файлового кеша ОС. [Методика и исходные измерения](benchmarks/README.md) содержат подробные условия и все результаты запусков.

## DAWG и использованная литература

Если СОВСЕМ КОРОТКО, то DAWG (Directed Acyclic Word Graph) представляет собой набор строк как ориентированный ациклический граф. В словарном варианте это детерминированный конечный автомат: состояния с одинаковыми допустимыми продолжениями объединяются, что позволяет компактно хранить словарь. Построение таких автоматов описано в работе:

- J. Daciuk, S. Mihov, B. W. Watson, R. E. Watson. [Incremental Construction of Minimal Acyclic Finite-State Automata](https://aclanthology.org/J00-1002/). Computational Linguistics, 26(1), 2000, с. 3-16. [PDF](https://aclanthology.org/J00-1002.pdf).

Практическая реализация этой структуры в [dawgdic](https://github.com/stil/dawgdic) использует представление double-array. На ней то основана библиотека [DAWG](https://github.com/pytries/DAWG). В `rs-morphy4` модуль [dictionary/dawg](src/dictionary/dawg) читает готовый бинарный индекс и извлекает записи с номерами парадигм и форм. Построение и минимизация автомата в текущей версии библиотеки я не делал. Может, в будущем, если будет необходимость, я и сделаю. Впрочем, для русского языка словарь в 2,5 млн слов и 1,5 млн форм занимает всего с десяток МБ, поэтому особой нужды в этом нет, мне кажется.
